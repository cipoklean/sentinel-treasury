01 / Premise

Elsewhere, an agent's budget is a line of app code

On a typical EVM chain, "spending limits" for an AI agent live in the same software the agent runs, or in one contract. One leaked key or one bug and they're gone. Sentinel moves each limit into a separate enforcer the agent cannot reach.

ThreatTypical agent walletSentinel on QoreChain
Agent key leaksAttacker can send funds anywhere the key can sign for.The chain rejects any tx whose target isn't the vault or registry, before execution.
Contract bugAll limits fall with the one contract that holds them.Two more independent limits live in the protocol: the EVM window and the abstract-account rule.
Large paymentApproved by whoever holds a classical key.Needs an operator ML-DSA-87 mandate, verified in Solidity by the pqcVerify precompile.
Agent tries to widen its scopeCalls an admin function with its own key.Widening needs the account's PQ key. The agent process never holds the recovery code it derives from.
Quantum adversaryForges ECDSA, owns everything.Forged ECDSA gets only the agent's bounded slice. Mandates and window control are post-quantum.

02 / Bounds

Four layers. Four different enforcers

Each ring is checked by different code at a different point in a transaction's life. Hover a layer to find it in the diagram.

L0consensus

Scoped EVM window

The agent's EOA can only broadcast EVM transactions inside a window opened by a hybrid-signed native tx. The window names its allowed targets; anything else is rejected at broadcast, with no contract code involved.

allowed_targets = [vault, registry]17,280 blocksmax 20 txsmax 4 QOR

L1x/abstractaccount

Abstract-account spending rules

The agent key is also linked as an authenticator on the operator's abstract account, with an EVM permission and a protocol-level spending rule. It's a second allowlist with its own budgets, kept by a different module.

rule sentinel-agent-evmallowed_evm_calls = [vault]1 QOR / tx5 QOR / dayexpires in 7 days

L2solidity + PQC precompiles

PolicyVault

Holds the treasury and re-checks every payment no matter what the agent decided: pause, vendor allowlist, per-tx cap, rolling daily cap. Above the threshold it needs an operator ML-DSA-87 mandate verified by pqcVerify (0x0A01). Admin calls re-check pqcKeyStatus (0x0A02). Refusals are emitted on-chain.

L3services

Agent & guardian

The agent scans the registry, decides, signs an EIP-712 receipt and calls pay. A separate guardian renews the window, issues mandates and runs the kill switch. The agent holds only its classical key, so it can't open its own window.

03 / Custody

Who holds which key, and what they can't do

Authority is split across three processes. The hot one, the agent, is also the one with the least power.

Operator · cold

Owner

ML-DSA-87 + ECDSA, hybrid-signed

  • Opens and closes EVM windows
  • Links authenticators and spending rules
  • Signs payment mandates above threshold
  • Sets policy, allowlist, pause

Guardian · warm

Supervisor

holds the agent's PQC recovery code

  • Renews the agent's scoped window when it runs low
  • Auto-issues mandates within an approval ceiling
  • Kill switch: closes the window, pauses the vault
  • Decides what to pay

Agent · hot

Sentinel

classical secp256k1 only

  • Scans invoices, decides, signs EIP-712 receipts
  • Calls pay on the vault
  • Open or widen its own window
  • Sign a mandate
  • Call any other contract

→ The agent's ML-DSA-87 key derives from QORE_PQC_RECOVERY_CODE, which only guardian/env.ts loads. agent/config.ts loads only PRIVATE_KEY.

04 / Lifecycle

The life of one payment

The agent's own judgement comes first, but the chain gets the final word, three times.

  1. 1

    Scan

  2. 2

    Decide

    Mirror the vault: pause → allowlist → per-tx → daily → threshold.

  3. 3

    Review

    An LLM may veto an approved payment. It can never approve a refused one.

    agent/llm.ts · DeepSeek
  4. 4

    Sign

    EIP-712 Decision receipt. decisionRef = keccak256(sig) travels on-chain.

    agent/receipt.ts

    Admit

    The node checks the scoped window: target, tx count, value, expiry.

    L0 · consensus
  6. 6

    L2 · PolicyVault
  7. 7

    Record

    PaymentExecuted or PaymentRefused. Refusals are on-chain too.

05 / Q-Day drill

On 18 Nov the attacker gets the key. Pick an attack

For the Q-Day Drill the agent account is the target: the attack bot receives Sentinel's classical ECDSA key, the same position a quantum adversary would be in. Here is what it can try and where each attempt stops.

    Drill day

    18 Nov

    The attack bot gets the agent's ECDSA private key.

    What it holds

    The agent's ECDSA key: valid signatures, a funded EOA, a live scoped window. It does not hold the PQ key, the operator account or the guardian.

    After the drill

    Rotate: setAgent → new scoped window → re-linked authenticator. The old key is left with nothing.
